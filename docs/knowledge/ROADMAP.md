# Дорожная карта и состояние задач

## Решение о продолжении

Общий цикл из **34 задач находится на паузе по решению владельца**. Эта база знаний и отдельные поручения по поддержке не возобновляют его целиком. Следующая задача получает собственный согласованный объём, ответственного и критерии приёмки.

Таблица сверена с сохранённой записью выполнения, а не со старым CSV, где почти всё оставалось «предлагается». История содержит **17 принятых задач, 8 частичных и 9 непринятых**. Это подтверждённый состав прежней записи, а не новый полный аудит всех модулей или число возможностей, доступных на каждом клиенте. См. [исторический checkpoint](../release-notes/plan-checkpoint.md).

При возобновлении конкретной задачи сначала проверить текущий код, связанный PR, выпуск и устройство. Не начинать принятую реализацию с нуля и не считать частичную готовой только по наличию исходника. В изменении обновить соответствующую строку и доступное подтверждение.

## Условные направления

- OCR использует тот же проверяемый ImportDraft и рассматривается после доказанной пользы текстового импорта.
- Web backup/restore требует отдельного проекта с restore-проверками и совместимостью наших шифрованных настроек.
- Оптимизация фоновых интеграций относится к действительно используемым источникам; облегчение анализатора — к выбранному режиму анализа.
- Vibe Map, заявки, музыкальный ассистент, свои файлы и private-profile import не становятся автоматически первыми задачами нового участника.
- Приёмка legacy AIO не доказывает изменение используемого split production.
- Обновление APK требует проверки N→N+1 с сохранением данных; размер файла и успешная сборка её не заменяют.

## Предложения по совместной разработке

Предложены защита main/dev, review перед merge и расширение полного Quality CI на dev PR. Эти настройки не считаются включёнными данным документом. Для изменения GitHub policy или workflows нужна отдельная задача с сохранением действующих проверок.

Для работы с новой задачей использовать [WORKFLOW](WORKFLOW.md), [STATE](STATE.md) и [шаблон обновления](templates/change.md). Активные назначения и ветки находятся в issues/PR, чтобы не поддерживать противоречивую вторую доску статусов.
