# Состояние проекта

## Продукт и код

| Область           | Реализованный охват                                                                              | Граница подтверждения                                                         |
| ----------------- | ------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------- |
| Web и PWA         | Каталог, поиск, плеер, очередь, Волна, миксы, коллекция, плейлисты, импорт, загрузки и настройки | Доступность внешних источников и приёмка устройства проверяются отдельно      |
| API и worker      | Пользовательские данные, предпочтения, source orchestration, фоновые задачи и проверки очереди   | Merge и успешный build не являются доказательством production deployment      |
| Flutter           | Музыкальный клиент с общей Android/iOS основой                                                   | Android — первый целевой выпуск; iOS требует отдельной macOS-сборки и приёмки |
| Общая база знаний | Версионируемый контекст, читаемый из AGENTS и обновляемый в PR                                   | Свежесть локальной копии зависит от обновления ветки                          |

Версии инструментов и APK берутся из [mobile/README.md](../../mobile/README.md), [pubspec.yaml](../../mobile/pubspec.yaml), [package manifests](../../package.json) и lockfiles. Не дублировать изменяемые версии в нескольких сводках.

## Подтверждённый выпуск

[Запись проверки источников и прокси](../release-notes/source-recovery-verification.md) содержит последний перенесённый в эту базу production checkpoint: полный source commit, состав обновления, реальные проверки сайта и ограничения. Это точка проверки, а не обещание постоянной доступности и не указание деплоить любой последующий `main`.

В действующем описанном пути аудио и извлечение подписанного URL используют один выделенный маршрут Soundspan; публичный каталог сохраняет отдельный HTTP/3-путь. Для Express обновлена зависимость proxy-addr, а доверие к forwarded identity определяется явно проверенной конфигурацией. MusicBrainz использует общий transport-reset cooldown API и worker. Конкретные порты, credentials и приватные route profiles здесь не хранятся.

## Приостановленная работа

- Общий цикл из 34 задач находится **на паузе по решению владельца**. Отдельные новые поручения не возобновляют его целиком.
- Синхронизация воспроизведения между устройствами отложена.
- Большой редизайн и переименование не объявляются завершёнными; согласованное направление описано в [решениях](DECISIONS.md).
- Публичная доступность APK, установленная версия на конкретном телефоне и приёмка updater N→N+1 не следуют из наличия исходников или подписанного файла.

Сохранённая приёмка и частичные результаты приведены в [дорожной карте](ROADMAP.md). Не повторять уже принятое с нуля и не закрывать частичное по одному совпадению имени файла.

## Непроверенное и наблюдения

- Короткий браузерный тест не доказывает длительный фон, Bluetooth, аудиофокус или отсутствие остановок на Pixel/Realme.
- Полный полученный audio-файл не равен приёмке всей очереди загрузок, PWA cold offline или обновления APK.
- Единичный пустой первый ответ QA-Волны и последующий ответ с треками не получили отдельной причинной диагностики. Не приписывать их исправление сетевому пакету без проверки.
- Успех одного CDN и исправление MusicBrainz retry amplification не доказывают доступность всего внешнего каталога.
- Сохранённое наблюдение GitHub — отсутствие защиты `main`/`dev` и неполный CI trigger для `dev` PR. Предложения исправления находятся в [WORKFLOW](WORKFLOW.md); настройки не считаются изменёнными без подтверждения GitHub.

## Как обновлять состояние

При принятии изменения указывать, что подтверждено в коде, что выпущено и что проверено на устройстве. Датированные измерения сохранять отдельной release note. Если не было свежей проверки, сохранять ограничение вместо переноса исторического PASS на новый коммит.
