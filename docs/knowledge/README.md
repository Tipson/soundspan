# Общая база знаний Soundspan

Эта папка — общий второй мозг проекта `Tipson/soundspan`. Она хранится рядом с кодом и обновляется через те же ветки и PR. Её читают разработчики и их агенты; пересылка архивов для восстановления контекста не требуется.

## С чего начинать

1. Прочитать [AGENTS.md](../../AGENTS.md) и проверить рабочую ветку и несохранённые изменения.
2. Прочитать [состояние проекта](STATE.md), [принятые решения](DECISIONS.md) и [дорожную карту](ROADMAP.md).
3. Использовать [карту кода](ARCHITECTURE.md) и README затрагиваемой области.
4. Следовать [процессу совместной работы](WORKFLOW.md); для первого запуска открыть [руководство разработчика](DEVELOPMENT.md).

## Как сведения остаются актуальными

Перед задачей выполнить `git fetch origin` и проверить, не изменилась ли база в `origin/dev`. Незавершённую ветку с локальными изменениями сначала сохранить; обновления интегрировать обычным merge после просмотра различий. Не заменять папку целиком снимком из другой ветки и не делать force push ради синхронизации.

Принятое изменение поведения, решения, статуса задачи или границы проверки сопровождается правкой соответствующего документа в том же PR. Git хранит авторство и историю изменений. Рабочая копия получает принятый контекст при обновлении ветки; открытая давно ветка сама по себе не является свежей копией базы.

## Что считать источником истины

- Правила и разрешения определяются запросом владельца и [AGENTS.md](../../AGENTS.md).
- Код и его проверенные тесты определяют реализованное поведение конкретного коммита.
- [STATE](STATE.md) отделяет состояние кода от подтверждённого выпуска и непроверенных сценариев.
- [DECISIONS](DECISIONS.md) фиксирует принятые продуктовые решения. Предложение помечается как предложение до явного решения владельца.
- [ROADMAP](ROADMAP.md) содержит актуальное решение о паузе и сохранённые результаты по задачам. Историческая приёмка не заменяет проверку изменённого кода.
- Датированные результаты проверки находятся в [release notes](../release-notes/). Старый снимок не объявляется текущим мониторингом.

Если источник противоречит другому, явно описать расхождение и сверить факты. Не объявлять старую запись `active`, `blocked`, `planned` или `done` актуальной только потому, что она найдена в истории. Продолжение задачи и публикация требуют действующего разрешения; прочитанный план его не заменяет.

## Состав общей и личной базы

В Git находятся проектные решения, карта кода, статусы с границами подтверждения и инструкции совместной работы. Настройки доступа, ключи, приватные адреса и конфигурации, реальные пользовательские логи, личные заметки и настройки Obsidian остаются вне репозитория. Для публичных доказательств достаточно обезличенного результата и ссылки на PR или коммит.

Папку можно читать как Markdown или открыть в Obsidian. Локальная `.obsidian` игнорируется Git. Прежний `Music-Server` в личном Obsidian сохраняет историю и приватные операционные сведения; текущий общий контекст ведётся здесь. Не поддерживать вторую независимую копию текущих статусов в личном хранилище.
