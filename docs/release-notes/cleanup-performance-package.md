## Состав

- Удалены пять модулей без входящих импортов: UI `FormElements`, `MediaCard` и старые Home `AudiobooksGrid`, `PodcastsGrid`, `MixesGrid`. Действующие страницы подкастов/аудиокниг и библиотечные карточки остаются.
- Удалён `date-fns` только из frontend; backend использует его и остаётся без изменений. `@types/howler` относится к devDependencies, сам Howler сохранён.
- Финальный split-frontend образ получает только production-зависимости и не содержит `.next/cache`. Кэш npm остаётся в BuildKit, пользовательские загрузки/кэши не затрагиваются.
- Перемешивание пропускает исчерпанные группы исполнителей: они отсортированы по убыванию размера, поэтому можно завершить внутренний цикл без изменения результата. Это оптимизация CPU подготовки очереди, не скорости получения аудио от YouTube.
- Селекторы тестов Волны учитывают доступные названия кнопок при коротких видимых подписях; сохранены проверки фактического запуска, паузы, настроек и очереди.

## Проверки

- `npm run test:unit`
- `npm run test:component`
- `npm run lint` (имеющийся warning-бюджет не изменён)
- `npx tsc --noEmit`
- `node --import tsx scripts/benchmark-artist-separation.ts`
- `node scripts/smoke-production-image.mjs IMAGE`

Исходный образ: `node_modules` 612 МиБ; `.next` 149 МиБ, включая 116 МиБ build cache; `date-fns` 28 МиБ. На синтетической очереди 10 000 записей, половина одного исполнителя, исходная обработка около 55 мс, оптимизированная около 1 мс на той же машине. Это не измерение ёмкости production или музыкального холодного старта.

## Границы выпуска

Только frontend; без миграций, изменений БД, credentials, источников музыки, серверных загрузок, backup-политики и соседних сервисов. Git push выполняет владелец. Пакет собирается из Git-архива, а не из исторического грязного дерева.
