# Плотность действий и жест плеера

Статус: frontend выпущен на production; целевые тесты, чистая сборка, полный frontend typecheck и проверка жеста на подключённом Android пройдены.

## Пакет

- Панели альбома, исполнителя, YouTube Music, обычного плейлиста и «Любимых треков»: воспроизведение, перемешивание и «Ещё». Подписанные второстепенные действия вынесены в общий Modal через portal, вне stacking context обложки.
- Сохранение, скачивание и применение лайков оставляют список открытым для отображения прогресса. Открытие следующего диалога сначала синхронно закрывает список, чтобы восстановление фокуса не перехватывало новый диалог.
- Верхняя ручка мобильного плеера получает `touch-action: none`; остальной контент сохраняет обычное поведение прокрутки. Ручка очереди уже имела это ограничение.
- Правило плотности закреплено в AGENTS.md. Зоны нажатия не уменьшены.

## Доказательства

- verify: 69 component tests, exit 0, включая проверки всех пяти панелей, состояний плеера, фокуса, прав владельца и прежних сценариев Home/Wave.
- verify: чистая production-сборка и полный frontend typecheck дерева `91b1e02d53b90e1061a94bde5e2bf6f6bb96607f`, exit 0 (`UI_DENSITY_BUILD_TYPECHECK_OK`).
- verify: браузерная копия — альбом «Группа крови» на 320/390 px, закрытие списка через Back без ухода со страницы; исполнитель 2CELLOS и его список действий на 1280 px; каталожный альбом на 390 px. «Любимые треки» на 390 px: компактная панель, открытие меню, переход в PlaylistSelector и закрытие Escape без изменения коллекций. Полный визуальный аудит всех экранов не проводился.
- verify: Pixel 10 Pro, Chrome (не standalone), системный свайп `640 480 → 640 1050`, 600 ms: исходная ручка с `touch-action: auto` вызвала reload (timeOrigin 1788820539242.5 → 1788820767863.4). Временное применение точного исправления `none` и повтор того же свайпа закрыли плеер с неизменным timeOrigin 1788820767863.4. Изменение DOM было диагностическим, не выпуском. CDP-синтетический touch сам по себе исходный баг не воспроизводил.
- lint: изменённые панели без ошибок/предупреждений; при добавлении OverlayPlayer строгий `--max-warnings=0` не проходит из-за двух существовавших предупреждений `set-state-in-effect` (восстановление вкладки и состояния drawer). Их присутствие подтверждено в HEAD; текущая правка их не меняет и не подавляет.
- verify: после выпуска и перезагрузки Chrome computed `touch-action: none` получен из опубликованного кода, без изменения DOM. Два системных свайпа — от ручки и от надписи — закрыли плеер без reload; timeOrigin оставался `1788821930122.5`.
- verify: production «Любимые треки» на Pixel — три основных действия в одной строке, высота 44 CSS px. Два цикла открытия «Ещё» системным нажатием на экран и одного Android Back закрыли диалог, сохранив `/playlist/my-liked`. В предшествующем автоматизированном открытии потребовались два Back; причина не установлена, в двух обычных системных циклах не повторилась. Это не доказательство отсутствия всех ошибок навигации.
