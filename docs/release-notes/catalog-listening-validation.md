# Каталог, скачивание и обращения: проверка кандидата

## Состояние

Локальная реализация. Production не изменялся. Расширения схемы базы данных нет. Отчёт не является подтверждением развёртывания или приёмки на физическом телефоне.

## Изменения

- Аутентифицированный поиск VK и Яндекса через сервисные подключения платформы. Ограничения параллелизма, ожидания, кэша и повторов; частичная недоступность отображается даже при пустой выдаче.
- Выбор конкретной версии записи. Объединение учитывает исполнителя, название, длительность и известный ISRC. Концертные версии и записи другой длительности не скрываются под оригиналом. Подтверждённая explicit-версия имеет приоритет; неизвестная маркировка остаётся неизвестной.
- Прямое воспроизведение, ручное скачивание и подготовка следующей сервисной записи. Постоянный адрес скачивания обновляет приватную сессию потока. Локальная копия воспроизводится без обращения к каталогу; device-only не допускает сетевую подмену.
- Обращения из меню текущего трека: неверная версия, нет звука, прерывание. Ограниченная офлайн-очередь изолирована по аккаунтам. Успешный ответ сервера требует сохранения уведомлений администраторам; повторная доставка идемпотентна.
- Состояния и итоги загрузок, офлайн-перемешивание и правила Волны проверены существующими поведенческими тестами. Алгоритм рекомендаций не менялся.

Прямые сервисные записи не поддерживают любимое, серверные плейлисты и совместное прослушивание. Эти действия защищены от ошибочной записи сервисного ID как локального или YouTube ID. Для расширения потребуется отдельная модель внешнего трека и проверка миграции медиатеки.

## Выполненная проверка

- Backend: `npm run build`; `npm run test:coverage -- --maxWorkers=2` — 617 прошедших наборов, 8 753 прошедших теста, 9 существующих пропусков. Покрытие строк 94,47%.
- Frontend: `npm run typecheck`, `npm run build`, `npm run lint` — успешно; lint сообщает 105 предупреждений и не содержит ошибок.
- Frontend: 1 702 unit-теста и 1 371 компонентный тест прошли. Включены выбор и сохранение ID версии при обновлении выдачи, пустая выдача при сбое источника, передача подготовленного следующего трека плееру, скачивание сервисной записи из меню и запрет сетевого запроса для скачанной копии.
- Контракт источников: семь тестов прошли. OpenAPI и маршруты покрыты backend-набором; проверки индекса маршрутов, канонизации ошибок, запрета новых source-scraping тестов и `git diff --check` прошли.
- Для действующих сервисных подключений VK и Яндекса выполнены read-only поиск и чтение начала конкретной записи «Альянс — На заре»: оба ответа 206, `audio/mpeg`, получены байты. Это не проверка полного трека, фонового перехода или слышимости.

## Adversarial review

Проверены границы роли и владельца, поздний ответ после смены аккаунта, отключение поколения подключения, preview и подмена выбранного ID, несовпадающие версии, таймаут некооперативного каталога, ограничение очереди диагностики, повтор после ошибки записи уведомления и сохранение ручного обращения при давлении автоматических событий.

Исправлены выявленные дефекты: цепочное объединение длительностей 180/182/184 с; потеря выбора версии при перестановке вариантов; несовпадающие лимиты метаданных поиска и resolve; отказ потребления подготовленного сервисного потока; загрузка runtime аудиодвижка статическим импортом интерфейса; скрытое сообщение о недоступности каталога при пустой выдаче.

В проверенном объёме открытых P0/P1 нет. Ограничения: уведомления используют общий существующий список администратора; новая нагрузочная проверка одновременного прямого прослушивания VK/Яндекса и проверка на физических телефонах не выполнялись.

## Порядок выпуска

Сначала backend с приёмом обращений, каталогом и адресами записей, затем frontend. Иначе старый backend отклонит новый тип обращения. Перед выпуском требуется отдельная проверка пользовательского сценария в браузере и плана отката. Production-образ и состояние сервисных подключений следует сохранить до замены контейнеров. Пользовательские данные и скачанные копии не удаляются.
