## Поведение

После подтверждённого прогресса терминальная сетевая ошибка или тайм-аут
буферизации дают одну попытку найти ту же запись на серверном источнике.
Новый поток загружается на паузе; длительность проверяется, позиция восстанавливается
до запуска. Очередь, лайки и идентичность записи сохраняются. Перемотка во время
ожидания обновляет целевую позицию. Пауза, смена записи и отзыв сессии отменяют
запоздавший результат. Общий срок восстановления ограничен 30 секундами.
Listen Together не выполняет независимую замену потока отдельного участника.

Кнопка паузы доступна в desktop, компактном и полноэкранном плеерах во время
восстановления. Запоздавшие metadata/timeupdate старого аудиоэлемента не переводят
восстановление в READY и не переписывают позицию. Отзыв авторизации освобождает
защиту старой попытки, не блокируя следующую сессию.

Стабильный URL предзагрузки сохраняет владение запросом и минутную паузу после
ошибки. Случайный `playbackSession` используется только при интерактивном запуске;
`preloadSession` продолжает разделять поколения авторизации.

## Измерения Яндекса

- verify: ступени 2, 4 и 8 параллельных полных потоков прошли на одном реальном
  подключении: всего 14 полных тел для «На заре», «Пьяная» и Billie Jean.
  SHA-256 совпали с ранее принятыми файлами; две Range-проверки каждого lease
  совпали побайтово. Отмена одного слушателя и отказ чужому пользователю проверены.
  Все занятые слоты освобождены.
- verify: поток читался с ограничением 256 KiB/s на слушателя. Заголовки приходили
  за 254–737 мс. Разрешение источника заняло 321–693 мс и выполнялось **последовательно
  перед потоковой ступенью**; это не замер параллельного поиска.
  Диагностический процесс достиг RSS 199 MiB и потратил 11 269 мс CPU за примерно
  175 секунд. Это не суммарное потребление production и не гарантия большей нагрузки.
- verify: фиксированная выборка 60 записей каталога (45–900 секунд, порядок по
  MD5 videoId, без истории пользователей) дала 19 уникальных совпадений,
  40 без совпадения и одно неоднозначное. Все 19 уникальных потоков отдали
  HTTP 206, `audio/mpeg`, 65536 байт. Полные тела этих 19 записей не проверялись.
  Результат описывает только эту выборку, а не долю покрытия всей музыки.

## Проверки и ревью

Обычное ревью проследило API boundary, владение попыткой, сохранение позиции,
загрузку MP3 через opaque URL, отмену, события движка и UI-паузу.

Adversarial review: **CLEAN в границах этого выпуска**. Проверены повторный сбой, дубли событий, поздняя загрузка,
смена очереди, отзыв авторизации, тайм-аут и неподходящая длительность.
В отдельной доказательной проверке обнаружены и исправлены гонка старого load
после ручного resume и оставшийся event guard после отзыва авторизации.
Повторный терминальный сбой явно останавливает движок: обычная native pause()
игнорирует его состояние error и могла оставлять воспроизведение из буфера.
Регрессии сначала падали и прошли после исправления.

- verify: Linux Node 24 — frontend build, typecheck, lint, полная unit-проверка
  (1640 passed), компонентная проверка (1292 passed) и coverage gate прошли.
  Узкий coverage gate проверяет 34 теста трёх своих файлов; его 100% не относятся
  ко всему изменению. ESLint: 0 ошибок, 105 предупреждений, включая предупреждение
  о настройке refs в новом тестовом fixture. Production-схема и backend-код не менялись.
- verify: `npm run verify:gates` прошёл в Windows. Linux-запуск инфраструктурных
  Docker-тестов был непригоден из-за отсутствия интеграции Docker CLI в WSL;
  эти проверки выполнены в Windows, без изменения правил или исключения тестов.
- verify: в изолированном Chrome-стенде искусственные MEDIA_ERR_NETWORK исчерпали
  внутренние retry движка. На принятом образе запись продолжилась с 73,5 секунды
  за 861,5 мс; дальнейший прогресс подтверждён. Второй сбой не создал нового
  resolve-запроса, остановил звук и сохранил «На заре» в очереди.
  Это fault injection, а не воспроизведение CAPTCHA самим YouTube.
- verify: при ручном resume и задержанном успешном ответе resolver (HTTP 200)
  кнопка паузы отменила восстановление; поздний ответ не запустил звук.
  Смена очереди, отзыв авторизации, поздние metadata/timeupdate, неподходящая
  длительность и общий deadline дополнительно проверены поведенческими тестами.
- verify: после исправления предзагрузки за 21 секунду наблюдения выполнен один
  неудачный preload вместо прежней серии запросов на каждом обновлении прогресса.

- verify: публичный HTTPS после выпуска — «На заре», «Пьяная», Billie Jean
  получены полностью, по две Range-проверки и повторный вход на запись прошли;

## Остаточные ограничения

Физические Android/iPhone и длительная нагрузка больше восьми слушателей не
проверены. При отсутствии точного совпадения очередь сохраняется, но звук не
гарантирован. Скрытая цензура без маркеров не определяется автоматически.
VK требует восстановления авторизации и реальной аудиоприёмки; HLS не реализован.
Несколько реплик playback API требуют распределённых leases. Устранение CAPTCHA
на стороне YouTube не доказано: резервный источник уменьшает её влияние только
для доступных точных совпадений.

Артефакты: `soundspan/output/provider-phase0/yandex-capacity-check.json`,
`catalog-coverage.json`, `jiosaavn-diagnostic-full.log`, `recovery-*.log` и
`browser-*.log`. Секреты в этот отчёт не включены.
