# Audius independent music catalog

Audius is an experimental, separate **limited-origin** catalog, not a mass-catalog replacement for YouTube. `FEATURE_AUDIUS` defaults to `false`. The existing authenticated `/api/system/features` response exposes only its boolean capability; the search shelf is hidden unless it is explicitly true. When enabled, the search page offers an explicit Audius search after the primary results. Selecting a source-labelled result enters the existing personal queue and player. It never changes YouTube ranking, automatic matching, or fallback.

## API contract

Use the same authenticated Soundspan API base URL as other `/api` calls.

- `GET /api/audius/search?query=RAC&limit=10` returns `{ source: "audius", tracks: [...] }`. Query length is 1–200 characters; limit is 1–20.
- `GET /api/audius/tracks/7AlA9/playback` revalidates the track and returns `{ source: "audius", trackId: "7AlA9", streamUrl: "<validated terminal Audius URL>" }` as JSON. It does not redirect the authenticated request. The URL can contain Audius' own short-lived signature, never Soundspan credentials, and must not be logged or persisted.

Both endpoints require the existing Soundspan authentication middleware. Disabled returns 404. Each account is limited to 60 requests/minute; process-wide metadata concurrency is four with immediate 503 shedding and no waiting queue. Requests have an eight-second timeout, propagate client cancellation, permit at most 1 MiB of metadata, reject redirects and use only the fixed official HTTPS API origin. A provider 429 activates a 30-second local cooldown; there are no automatic retries. Metadata and full-stream access are re-read before each playback resolution rather than shared across cached authorization decisions.

The player consumes `streamUrl` **without Soundspan Authorization, X-API-Key, cookies or query tokens** (`withCredentials: false`, native `crossOrigin: anonymous`). A current playback/auth-generation lease owns resolution and discards late results after cancellation. Queue metadata retains `audius:<provider-id>`, not the signed URL. The URL is re-resolved each load. Automatic preload, device download, Listen Together, playlist/library writes and history/recommendation writes are deliberately unsupported for this source. Queue-to-playlist conversion validates all references before creating a playlist, so playback-only entries cannot create partial playlists.

Resolution has one shared eight-second deadline across metadata, DNS and transport. The transport permits at most three HTTP requests: the fixed official GET redirect, one permitted content node, and optionally the exact supported CDN. Automatic redirects are disabled. Each destination passes the existing public-DNS/connect-time rebinding protection; unknown origins are rejected before DNS/I/O. Content and CDN qualification uses GET `Range: bytes=0-0` because provider signatures can be method-specific. Only terminal 206 `audio/*` with `Content-Range: bytes 0-0/<positive size>` qualifies. Every response body is immediately destroyed without reading media into application buffers. Unsupported or inaccessible nodes return 422 before the audio engine loads; deadline failure is 502, actual caller cancellation is 499. There is no media proxy or background retry.

The shared media policy and CSP permit exactly `creatornode.audius.co`, `audius-content-7.figment.io`, `audius-02.staked.cloud`, and `validator.eeba4a6ca56a0d87af802270217c2a51.r2.cloudflarestorage.com`. The first three require the signed CID-stream path/query contract. The R2 origin is accepted only as a secondary redirect from a permitted content node, with the same CID, the observed `/WRb/<CIDv0>` path, and exactly the eight observed AWS signed-GET parameters (ENAM/s3 scope, host-only signed headers, expiry at most 7,200 seconds). Its provider signature is a temporary bearer capability, not a Soundspan credential; do not log or persist it. Signature validity is checked by the provider's terminal GET, not asserted by the URL-shape validator. No host wildcards, other storage accounts, arbitrary HTTPS or general credential parameters are allowed. Enforced CSP retains all other directives unchanged. This deliberately excludes other nodes and storage layouts; it is **not stable coverage of the Audius catalog**. A same-origin media transport would require its own scoped design and acceptance, not part of this adapter.

## Recording identity and access

Playback-only capability is enforced in the actual action surfaces, not just API validation: Mini/Full/Overlay/Queue do not mount preference queries for Audius; overflow menus omit playlist and download actions while keeping queue operations. Overlay's separate playlist button and queue saving are also hidden when the track/queue cannot be persisted. Local and YouTube actions retain their existing behavior.

Entries retain provider id, exact title, uploader name/handle, verification flag, duration, Audius attribution link and `source: "audius"`. The uploader name and verified flag do not establish a match to a recording on another service. A cover, live version or remix retains its original version text and is never silently substituted for the requested original.

Queue metadata keeps the permanent public attribution page as `sourcePageUrl`. The track menu revalidates restored metadata before offering an Audius link in a separate tab with no opener or referrer; it never uses a signed media URL or carries Soundspan credentials to that page.

Only affirmative `is_streamable=true`, `is_stream_gated=false`, public/not-deleted metadata, `access.stream=true` and absent stream conditions qualify. Duration must be finite, positive and at most 24 hours. Missing access metadata, gated/purchase content, malformed identity or unsafe attribution paths are rejected. `fullStreamAvailable` means the official metadata allows the full stream endpoint; it is not proof that the complete file has decoded on the listening device. `automaticFallbackEligible=false` and `downloadAllowed=false` are intentional contract fields. Availability of streaming does not grant offline downloading or republication permission.

## Provider references and verification boundaries

The adapter uses the [official Audius REST API](https://docs.audius.co/api/) and the [official SDK model and gating semantics](https://github.com/audiusproject/apps). It uses no borrowed API key. Public unauthenticated endpoint availability is not a contractual quota guarantee; if the provider requires credentials or throttles access, surface the error and configure an approved integration before rollout rather than importing third-party keys.

The earlier bounded evidence `output/audius-provider-smoke/evidence.json` covers public search/detail and 64 KiB of a full-stream endpoint. A pre-policy Chromium smoke subsequently decoded a 236.719-second stream (metadata 237 seconds), advanced media time by 0.479 seconds, and observed no Soundspan credentials on either external request; this was muted and does not establish audible acceptance.

The retained negative strict-policy evidence is `output/playwright/audius-playback/result.json`: one search and one resolve returned a deliberate 422, with enforced CSP and no external audio request, when secondary storage redirects were unsupported. `output/playwright/audius-playback/cdn-acceptance.json` retains the separate runner failures. The authorized corrected run is `output/playwright/audius-playback/result-three.json`: the runner completed one search and three distinct playback resolves, and all three returned 422 before any external browser audio request. This establishes a live adapter rejection, not its exact transport or metadata cause; the report does not retain the rejection stage. Its **live-playback gate remains blocked**. A successful one-byte R2 response and deterministic tests do not prove browser playback. Browser evidence does not establish production readiness, full-file decoding, Safari support, full catalog coverage or concurrent listener capacity. Do not enable globally on the strength of unit tests.
