# Серверные источники музыки

Status: shipped (partial: Yandex; VK awaiting credentials and audio acceptance)

Яндекс подключён и проверен в production. Адаптер VK реализован, но остаётся
выключенным до получения токена и проверки полного аудиопотока.

## Цель и границы

Пользователь входит только в Soundspan. Выделенные подключения музыкальных
источников настраиваются администратором, credentials остаются на сервере.
История, очередь и лайки сохраняют исходную идентичность записи при переключении.
Успех означает проверенный полный аудиопоток, перемотку и параллельные сессии,
а не только успешный поиск или подготовленный адаптер.

## Решение по runtime

Система использует адаптеры в существующем TypeScript backend: Yandex и VK
разрешаются через HTTP API, декодирование остаётся в браузере. Это уточнение
предварительного выбора Phase 0: отдельный Java-фасад и Lavalink не развёрнуты.
Переиспользованы опубликованные протоколы, а не весь список возможностей LavaSrc.
Для расширения на HLS и другие direct providers выбор runtime остаётся открытым.

Нельзя выдавать synthetic fixture за проверку реального provider. Открытая
браузерная сессия не считается настроенным серверным подключением. CAPTCHA
фиксируется как отдельный upstream-отказ; резервный источник обеспечивает
доступность записи, но не доказывает устранение challenge на стороне YouTube.

## Подключение и доступ

Администратор управляет источниками в секции `playback-sources`. Токен записывается
через `PUT /api/music-sources/connections/{provider}`; ответ и список подключений
не содержат секретов. `MusicSourceConnection.token` использует существующий
settings cipher и включён в инвентаризацию и миграцию зашифрованных колонок.
Сохранение, включение, отключение и замена токена меняют его поколение.
Отключение через API немедленно отменяет активные запросы и старые leases.

Поиск для диагностики доступен только администратору. Кнопка проверки звука
ограничивает resolver выбранным источником. Полный поток и перемотку оператор
проверяет отдельно; успешный поиск или первый байт не означают пройденную приёмку.
Статус «включён» означает конфигурацию, а не подтверждённую работоспособность.
Пользователю Soundspan внешние токены не нужны.

## Воспроизведение и ограничения

- Браузер создаёт отдельный `playbackSession` для попытки запуска. При первоначальном
  отказе YouTube backend ищет точную запись, проверяет доступность первых байтов
  и выдаёт 307 на собственный URL lease. История, очередь и идентичность трека не меняются.
- При включённом резерве первоначальная попытка YouTube ограничена 60 секундами,
  resolver — 16 секундами. Без настроенных источников сохраняется прежний timeout.
  Таймер первоначального ожидания снимается после получения потока; отмена
  со стороны слушателя действует на протяжении передачи аудио.
  Предзагрузка не запускает дополнительные источники. Полный YouTube-кэш можно
  переиспользовать между сессиями; ответы резервных источников не попадают в него.
- После получения исходного потока представление закреплено. Смена кодека или
  источника посередине byte-range сессии запрещена. Автоматическое возобновление
  с прежней позиции на другом источнике после начавшегося воспроизведения **не реализовано**.
- Проверяются исполнитель, название, длительность, ISRC и маркеры версий.
  Preview, неоднозначные совпадения и известные clean-замены отклоняются.
  Скрытая цензура при отсутствующих метаданных не определяется автоматически.
- Yandex поддерживает полный MP3 по download-info. VK поддерживает полный прямой
  HTTP-аудиопоток; HLS (`.m3u8`) отклоняется. Реальная полнота каталогов не измерена.
- Потоки закреплены за пользователем, провайдером, поколением токена и валидатором
  представления. Range, If-Range, HEAD, 416, отмена и предел размера проверяются.
  Подписанные CDN URL остаются на сервере; DNS закрепляется после проверки IP.
- Runtime рассчитан на **одну реплику playback API**: до двух одновременных
  разрешений, восьми потоков на поколение подключения, 1000 leases на один час.
  Это защитные пределы кода, а не измеренная ёмкость сервисного аккаунта.
  Restart инвалидирует leases; распределённое хранение перед масштабированием обязательно.

## Источники протокола и открытые вопросы

[LavaSrc](https://github.com/topi314/LavaSrc) использован для проверки матрицы и
требований авторизации. Контрольная формула download-info сверена с
[Yandex Music API client](https://github.com/MarshalX/yandex-music-api/blob/main/yandex_music/download_info.py),
передача VK токена в POST-форме — с
[официальным VK SDK](https://github.com/VKCOM/vk-php-sdk/blob/master/src/VK/Client/VKApiRequest.php).

Публичный [Bedrock](https://github.com/feralbureau/bedrock-api) использует mirroring
для части каталогов. Его разрешение по первому поисковому совпадению с удалением
маркеров версии не переносится в Soundspan. Открытый код не доказывает устройство
текущего production-backend [Mimose](https://mimose.fun).

До production требуются пригодные для серверного использования подключения
Yandex/VK, реальное полное воспроизведение, два seek, повторный запуск, параллельные
слушатели и проверка выбранных версий. Открытые вкладки и семейная подписка сами
по себе этих доказательств не дают. Снимок проверок и граница выпуска:
[отчёт приёмки](../release-notes/server-music-sources-acceptance.md).
